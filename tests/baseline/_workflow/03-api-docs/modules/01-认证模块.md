# 认证模块 API 文档

> Controller: `AuthController` `CaptchaController` | Base URL: `http://localhost:8080` | Auth: Sa-Token JWT `Authorization: Bearer {token}` + `clientid: e5cd7e4891bf95d1d19206ce24a7b32e`

## 请求头

| 头名称 | 值 | 说明 |
|--------|-----|------|
| Content-Type | `application/json` | 请求体格式 |
| Authorization | `Bearer {token}` | Sa-Token JWT 令牌，登录后获取 |
| clientid | `e5cd7e4891bf95d1d19206ce24a7b32e` | 客户端 ID，与 Token 绑定 |

---

### 1 用户登录

| 属性 | 值 |
|------|-----|
| **请求方式** | `POST` |
| **接口路径** | `/auth/login` |
| **接口说明** | 用户登录，支持密码/短信/邮箱/小程序/第三方社交多种登录方式，根据 `grantType` 字段自动分发到对应的认证策略 |
| **认证方式** | 无需认证 |
| **权限要求** | 无 |
| **标签** | 认证、登录 |
| **加密** | `@ApiEncrypt` 请求体整体加密传输 |

---

#### 请求

**请求头**: [公开]

请求体加密后为字符串，解密后为 JSON 对象。基础结构参见 [LoginBody](../entities/LoginBody.md)，核心字段 `clientId`、`grantType` 必填。根据 `grantType` 的值，需额外携带对应子类 DTO 的字段：

| grantType | 对应 DTO | 额外必填字段 |
|-----------|----------|------------|
| `password` | [PasswordLoginBody](../entities/PasswordLoginBody.md) | `username`、`password` |
| `sms` | [SmsLoginBody](../entities/SmsLoginBody.md) | `phonenumber`、`smsCode` |
| `email` | [EmailLoginBody](../entities/EmailLoginBody.md) | `email`、`emailCode` |
| `xcx` | [XcxLoginBody](../entities/XcxLoginBody.md) | `xcxCode` |
| `social` | [SocialLoginBody](../entities/SocialLoginBody.md) | `source`、`socialCode`、`socialState` |

**JSON 示例**（密码登录）：

```json
{
  "clientId": "e5cd7e4891bf95d1d19206ce24a7b32e",
  "grantType": "password",
  "tenantId": "100000",
  "username": "admin",
  "password": "admin123",
  "code": "1234",
  "uuid": "a1b2c3d4e5f6"
}
```

---

#### 业务规则

| 规则编号 | 规则描述 |
|:----:|------|
| R01 | 请求体经 `@ApiEncrypt` 整体加密，后端先解密再解析 JSON |
| R02 | 系统根据 `grantType` 通过 Spring 容器查找 `{grantType}AuthStrategy` Bean 进行策略分发 |
| R03 | 密码登录时若系统开启了图形验证码，则必须校验 `code` + `uuid` |
| R04 | 登录错误次数达到配置上限（默认 `maxRetryCount`）后锁定 `lockTime` 分钟，期间所有密码/验证码校验均直接拒绝 |
| R05 | 短信/邮箱验证码从 Redis 读取，key 为 `captcha_code:{phonenumber}` 或 `captcha_code:{email}`，校验成功后不自动删除 |
| R06 | 图形验证码从 Redis 读取后立即删除，一次性使用 |
| R07 | 登录成功 5 秒后通过 SSE 向登录用户推送欢迎消息 |
| R08 | 登录成功后生成 Sa-Token JWT，超时时间由客户端配置（`SysClientVo.timeout`）决定 |

### 2 获取第三方登录跳转URL

| 属性 | 值 |
|------|-----|
| **请求方式** | `GET` |
| **接口路径** | `/auth/binding/{source}` |
| **接口说明** | 根据第三方平台标识生成 OAuth 授权跳转 URL |
| **认证方式** | 无需认证 |
| **权限要求** | 无 |
| **标签** | 认证、第三方登录 |

---

#### 请求

**请求头**: [公开]

**路径参数**

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|:---:|------|------|
| `source` | String | 是 | 第三方登录平台标识（如 github、gitee、wechat_open） | `"github"` |

**查询参数**

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|:---:|------|------|
| `tenantId` | String | 是 | 租户ID | `"100000"` |
| `domain` | String | 是 | 前端域名（用于回调 state 参数中携带） | `"https://example.com"` |

---

#### 响应

##### 成功响应 — HTTP 200

响应体为 `R<String>`，`data` 字段为第三方平台的 OAuth 授权跳转 URL。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": "https://github.com/login/oauth/authorize?client_id=xxx&redirect_uri=xxx&state=..."
}
```

##### 错误响应

| HTTP | code | 触发条件 | msg |
|:----:|:----:|----------|-----|
| 200 | 200 | 获取成功 | `"操作成功"` |
| 200 | 500 | `source` 对应的平台未配置 | `"{source}平台账号暂不支持"` |

---

#### 业务规则

| 规则编号 | 规则描述 |
|:----:|------|
| R01 | 系统从 `SocialProperties` 配置中查找 `source` 对应的平台配置 |
| R02 | state 参数通过 `AuthStateUtils.createState()` 生成，用于防 CSRF 攻击 |
| R03 | state 中 Base64 编码了 `tenantId` 和 `domain`，回调时解码使用 |

#### 业务规则

| 规则编号 | 规则描述 |
|:----:|------|
| R01 | 接口需要先登录（`StpUtil.checkLogin()`），将第三方账号与当前登录用户绑定 |
| R02 | 通过 `lock4j` 分布式锁防止并发重复绑定 |
| R03 | 同一平台（source）同一用户只能绑定一个第三方账号，重复绑定会更新信息而非新增 |
| R04 | 若同一 `authId`（source + uuid）已被其他用户绑定，抛出异常 |

**验证码开启时**：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "captchaEnabled": true,
    "uuid": "a1b2c3d4e5f6",
    "img": "data:image/png;base64,iVBORw0KGgo..."
  }
}
```

**验证码关闭时**：

  "code": 200,

  }

|:----:|:----:|----------|-----|
| 200 | 200 | 生成成功 | `"操作成功"` |

---

#### 业务规则

| 规则编号 | 规则描述 |
|:----:|------|
| R01 | 验证码开关由 `CaptchaProperties.enable` 配置控制，关闭时返回 `captchaEnabled: false` |
| R02 | 验证码类型由配置 `captcha.type` 决定：`math` 为数学运算（如 `1+2=?`），其他为随机字符（如 `aB3d`） |
| R03 | 数学验证码结果通过 SpEL 表达式计算后存入 Redis |
| R04 | 验证码图片通过自定义 `WaveAndCircleCaptcha` 生成，带波浪线和圆圈干扰 |
| R05 | 验证码 key 为 `captcha_code:{uuid}`，有效期由 `Constants.CAPTCHA_EXPIRATION` 控制（默认 2 分钟） |
| R06 | 该接口不限流（限流在内部 `getCodeImpl` 方法上，仅在验证码开启时生效：60 秒内每 IP 最多 10 次） |
| R07 | 整个 CaptchaController 类标注了 `@SaIgnore`，所有接口均无需认证 |

## 全局错误处理说明

本模块涉及的异常处理链：

| 异常类型 | 全局处理器 | HTTP 状态码 | code | msg 来源 |
|----------|-----------|:----------:|:----:|---------|
| `ConstraintViolationException` | `constraintViolationException` | 200 | 500 | 校验注解的 `message` 属性（i18n 解析后） |
| `BindException` | `handleBindException` | 200 | 500 | 校验注解的 `message` 属性（i18n 解析后） |
| `MethodArgumentNotValidException` | `handleMethodArgumentNotValidException` | 200 | 500 | 校验注解的 `message` 属性（i18n 解析后） |
| `HandlerMethodValidationException` | `handlerMethodValidationException` | 200 | 500 | 校验注解的 `message` 属性（i18n 解析后） |
| `ServiceException` | `handleServiceException` | 200 | 500 | `e.getMessage()` 或构造时传入的消息 |
| `UserException` (extends `BaseException`) | `handleBaseException` | 200 | 500 | `MessageUtils.message(code, args)` 解析后的 i18n 消息 |
| `CaptchaException` (extends `UserException`) | `handleBaseException` | 200 | 500 | i18n key `user.jcaptcha.error` → `"验证码错误"` |
| `CaptchaExpireException` (extends `UserException`) | `handleBaseException` | 200 | 500 | i18n key `user.jcaptcha.expire` → `"验证码已失效"` |
| `TenantException` (extends `BaseException`) | `handleBaseException` | 200 | 500 | 对应租户 i18n key 解析后的消息 |
| Sa-Token `NotLoginException` | Sa-Token 框架拦截 | 401 | 401 | `"认证失败，无法访问系统资源"` |

> 注：`UserException`、`CaptchaException`、`CaptchaExpireException`、`TenantException` 均继承自 `BaseException`，其 `getMessage()` 方法通过 `MessageUtils.message(code, args)` 从 `messages_zh_CN.properties` 解析 i18n 翻译。
