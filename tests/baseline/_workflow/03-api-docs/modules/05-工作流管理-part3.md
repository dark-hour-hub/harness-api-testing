#### 响应

##### 成功响应 — HTTP 200

  "msg": "提交成功",
  "data": {

##### 错误响应

| HTTP | code | 触发条件 | msg |
|:----:|:----:|----------|-----|
| 200 | 200 | 操作成功 | `"提交成功"` |
| 401 | 401 | Token 缺失或失效 | `"认证失败，无法访问系统资源"` |
| 200 | 500 | `businessId` 为空（Service 校验） | `"启动工作流时必须包含业务ID"` |
| 200 | 500 | 流程定义编码未发布 | `"流程【{flowCode}】未发布，请先在流程设计器中发布流程定义"` |
| 200 | 500 | 流程启动后未生成任务 | `"流程启动失败，未生成任务"` |
| 200 | 500 | 流程第一个环节不是申请人节点 | `"请检查流程第一个环节是否为申请人！"` |
| 200 | 500 | 已存在流程实例但缺少任务 | `"流程实例缺少任务，请检查流程定义配置"` |
| 200 | 500 | `businessId` 为空（`@NotBlank` 校验） | `"业务ID不能为空"` |
| 200 | 500 | `flowCode` 为空（`@NotBlank` 校验） | `"流程定义编码不能为空"` |
| 200 | 500 | 重复提交 | `"不允许重复提交，请稍候再试"` |
| 200 | 500 | 已存在流程实例但状态不允许再次启动（checkStartStatus） | 业务状态校验异常消息 |

---

#### 业务规则

| 规则 | 说明 |
|------|------|
| 业务ID重复检测 | 同一 `businessId` 若已存在流程实例，则直接返回已有实例的任务信息，不创建新实例 |
| 流程定义校验 | `flowCode` 必须对应已发布的流程定义，否则报错 |
| 自动注入变量 | 框架自动注入发起人 (`initiator`)、发起人部门 (`initiatorDeptId`)、业务ID (`businessId`) 到流程变量中 |
| 申请人节点校验 | 流程定义第一个环节必须是申请人节点，否则启动失败 |
| 分布式锁 | 使用 `@Lock4j` 对 `flowCode + businessId` 加锁，防止并发重复创建 |
