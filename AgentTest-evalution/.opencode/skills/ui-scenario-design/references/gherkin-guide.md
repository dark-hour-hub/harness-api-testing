# Gherkin 场景编写指南（通用步骤 DSL）

## 定位信息来源

写场景前，先从前端源码确认以下定位文案（决定场景能否可靠执行）：

| 元素类型 | 源码位置 | Gherkin 中使用的文案 |
|----------|----------|----------------------|
| 按钮 | `<el-button>新增图书</el-button>` | `点击按钮 "新增图书"` |
| 菜单项 | `<el-menu-item index="/books">图书管理</el-menu-item>` | `点击菜单 "图书管理"` |
| 输入框 | `<el-input placeholder="请输入书名" />` | `在 "请输入书名" 输入框中输入 "..."` |
| 提示 | `ElMessage.success('新增成功')` | `应看到提示 "新增成功"` |
| 表格断言 | 表格渲染的数据列 | `表格应包含 "测试图书"` |

**关键点**：
- 输入框优先用 **placeholder** 文案（Element Plus 的 `get_by_label` 可能因 label/id 未关联而失效）
- 按钮/菜单用**可见文本**（`get_by_role` 的 name 匹配，忽略 disabled）
- 提示文案必须与前端 `ElMessage` 里的字符串**完全一致**

## 场景结构模板

```gherkin
Feature: <模块名>
  <业务背景描述，可多行>

  Scenario: <英文场景名，简短描述>
    Given 打开首页
    When 点击菜单 "图书管理"
    And 点击按钮 "新增图书"
    And 在 "如 978-7-111-12345-8" 输入框中输入 "978-7-111-00001-1"
    And 在 "请输入书名" 输入框中输入 "测试图书"
    And 点击按钮 "保存"
    Then 应看到提示 "新增成功"
    And 表格应包含 "测试图书"
```

## 场景变量与 DB 断言（防假成功）

关键写操作（创建/编辑/删除）除 UI 提示断言外，用场景变量 + DB 断言证明数据真实落库：

```gherkin
Scenario: create book
  Given 打开首页
  When 点击按钮 "新增图书"
  And 令 $isbn = "978-7-111-${ts}"
  And 在 "如 978-7-111-12345-8" 输入框中输入 "$isbn"
  And 点击按钮 "保存"
  Then 应看到提示 "新增成功"
  And 且数据已保存到 "BOOK_CREATE_001"
```

| 元素 | 示例 | 说明 |
|------|------|------|
| 场景变量 | `令 $isbn = "978-7-111-${ts}"` | 声明变量（值可含 `${ts}` 动态值，声明时展开）；仅当前 Scenario 作用域 |
| 值引用 | `在 "..." 输入框中输入 "$isbn"` | 输入/日期步骤支持 `$变量` 引用；`${...}` 与 `$.answer` 不受影响 |
| DB 断言 | `且数据已保存到 "BOOK_CREATE_001"` | 映射 id 来自 db-asserts.yaml；生成器校验 id/表/列/变量 |

规则：
1. **先声明后使用**（生成器会校验，违反则生成中止）
2. 映射由 AI 从需求文档「数据变更映射」表翻译 + 测试工程师确认，业务不写 yaml
3. 断言时机：操作步骤已完成 busy + API 同步（api_sync_rules）后自动查库
4. 需求文档无映射的操作 → 不用 DB 断言，保持 UI 提示断言

## 编写规则

1. **Given 描述前置状态**，When 描述操作，Then 描述预期结果；`And`/`But` 继承上一步类型
2. **【关键字继承陷阱，必读】`And` 继承前一行关键字**：`Given 打开首页` 之后的跳转/操作步骤
   （点击菜单/点击链接/点击按钮/输入框）必须显式写成 `When`，绝不能写成 `And`——
   否则 And 会继承 Given 关键字，而常用步骤库只注册了 when/given 双形态，
   `StepDefinitionNotFoundError` 只会在执行期才暴露。规则：**「Given 行之后紧跟 When」**。
3. **引号内的值用双引号** `"值"`，步骤模板中的引号是解析边界
4. **登录**统一用 `以账号 "<用户名>" 密码 "<密码>" 登录`，账号来自 `config.yaml` 的 accounts
5. **打开首页**：不写 URL（从 `config.yaml` 读取），如需覆盖写 `打开首页 "<url>"`
6. **弹窗确认**：Element Plus 的 `ElMessageBox.confirm` 确认按钮是「确定」，取消是「取消」
7. **一个 Scenario 一个业务意图**，多个意图拆多个 Scenario

## 完整示例（图书管理系统）

```gherkin
Feature: 图书管理
  管理员对图书进行增删改查，普通用户可借阅图书

  Scenario: admin create book
    Given 打开首页
    When 点击菜单 "图书管理"
    And 点击按钮 "新增图书"
    And 在 "如 978-7-111-12345-8" 输入框中输入 "978-7-111-00001-1"
    And 在 "请输入书名" 输入框中输入 "测试图书"
    And 在 "请输入作者" 输入框中输入 "测试作者"
    And 点击按钮 "保存"
    Then 应看到提示 "新增成功"
    And 表格应包含 "测试图书"

  Scenario: user borrow book
    Given 打开首页
    When 点击菜单 "图书管理"
    And 点击按钮 "借阅"
    And 点击按钮 "确定"
    Then 应看到提示 "借阅成功"
```

## 注意事项

- pytest-bdd 的 `scenarios()` 会把 scenario 名 slug 化成测试函数名，**scenario 名用英文**
- 表格里「借阅」按钮每行一个，通用步骤「点击按钮」自动选择第一个 **enabled** 的按钮（跳过库存为 0 的 disabled 行）
- 涉及写操作的场景（新增/删除）依赖后端数据状态，重复执行可能因唯一约束（如 ISBN 冲突）失败，必要时在场景里使用动态值
