# 测试用例模块 API 文档

> Controller: `com.czbank.aicgs.evaluation.testcase.adapter.in.web.TestCaseController`、`com.czbank.aicgs.evaluation.testcase.adapter.in.web.TestCaseExcelImportController` | Base URL: `http://localhost:8080` | Auth: 无（auth_type: none，所有接口公开访问）

## 请求头

| 头名称 | 值 | 说明 |
|--------|-----|------|
| Content-Type | `application/json` | 请求体格式；Excel 导入接口（`/api/test-cases/import/excel`）必须使用 `multipart/form-data` |
| X-Trace-Id | `{自定义字符串}` | 可选，链路追踪 ID（TraceIdFilter 透传并回写响应头）；缺失时服务端生成 32 位十六进制 UUID，永不因缺失报错 |

> 认证说明：全项目无任何认证机制，无 `Authorization`/`clientid` 等鉴权头，无权限模型。
>
> 响应包装：所有接口响应体均为 [ApiResponse](../entities/ApiResponse.md)（code=`"200"`/message=`"success"` 表示成功）；分页数据为 [PageResult](../entities/PageResult.md)（items/page/pageSize/total，pageSize 上限 100）。
>
> 错误响应统一由 `GlobalExceptionHandler` 处理：HTTP 状态码 = ErrorCode.httpStatus()，响应体 code = ErrorCode.name()，message = ErrorCode.defaultMessage()（硬编码，无 i18n）。本模块涉及的错误码：
>
> | code | HTTP | message |
> |------|:----:|---------|
> | COMMON_400_VALIDATION | 400 | `"Validation failed"` |
> | COMMON_404_RESOURCE | 404 | `"Resource not found"` |
> | COMMON_409_CONFLICT | 409 | `"Resource conflict"` |
> | TEST_CASE_400_RULE | 400 | `"Invalid test case rule"` |
> | TEST_CASE_NOT_FOUND | 404 | `"Test case not found"` |
> | COMMON_500_INTERNAL | 500 | `"Internal server error"` |
>
> 说明：错误码与 HTTP 状态码一一对应（`ErrorCode.httpStatus()`）；校验/导入场景返回的错误条目见各接口的 [ImportError](../entities/ImportError.md) 说明。

#### 请求

**请求头**: [公开]

**查询参数表**（全部由 Controller 手工解析，类型声明为 String 但按下列规则转换）：

| 参数名 | 类型 | 必填 | 匹配方式 | 说明 | 示例 |
|--------|------|:---:|:---:|------|------|
| `indicatorId` | String | 否 | eq | 指标 ID 精确过滤（`t.indicator_id = ?`）；必须为正整数，非数字/小于 1 报 400 | `1001` |
| `dimensionCode` | String | 否 | eq | 指标维度编码精确过滤（JOIN indicator_dimension 按 `dimension_code` 匹配） | `"SAFETY"` |
| `categoryCode` | String | 否 | eq | 指标分类编码精确过滤（JOIN indicator_category 按 `category_code` 匹配） | `"PROMPT_INJECTION"` |
| `caseType` | String | 否 | eq | 用例类型精确过滤，合法枚举 `SINGLE_TURN`/`MULTI_TURN`/`TOOL_CALL`/`MANUAL_AUDIT`；非法值报 400 | `"SINGLE_TURN"` |
| `enabled` | String | 否 | eq | 启用状态精确过滤，合法值 `true`/`false`（大小写不敏感）；非法值报 400 | `"true"` |
| `page` | String | 否 | — | 页码，从 1 开始，默认 `1`；小于 1 或非数字报 400 | `1` |
| `pageSize` | String | 否 | — | 每页条数，默认 `20`，范围 1~100；越界或非数字报 400 | `20` |

> 匹配方式映射：`eq`=精确匹配。dimensionCode/categoryCode 经由指标维度/分类表 JOIN 后精确匹配，无模糊查询。
>
> 排序固定：`ORDER BY updated_at DESC, id DESC`，无排序参数（不支持 orderByColumn/isAsc）。
>
> 空值/空白字符串的筛选参数按未传处理（SQL 层 `<if>` 判空跳过）；软删除（deleted_at IS NOT NULL）的用例不参与查询。

无请求体。

##### 错误响应

| HTTP | code | 触发条件 | msg |
|:----:|:----:|----------|-----|
| 400 | COMMON_400_VALIDATION | 请求体不满足 `@Valid` 约束（data 为字段错误 Map，如 `{"weight": "must be greater than 0"}`）；请求体非 JSON 或字段类型错误 | `"Validation failed"` |
| 400 | TEST_CASE_400_RULE | 服务层规则校验失败：indicatorId 不存在或非启用 CORE 指标、SINGLE_TURN 缺 question、MULTI_TURN 轮次 <2 或含空值、TOOL_CALL 缺 expectedTool、rules 为空或无启用规则、规则配置非法等（data=null） | `"Invalid test case rule"` |
| 409 | COMMON_409_CONFLICT | `caseCode` + `version` 组合已存在（软删除的用例同样命中，`findByCodeAndVersion` 不过滤 deleted_at） | `"Resource conflict"` |

---

#### 业务规则

- 两段式校验：先 `@Valid`（Bean Validation，400 + 字段 Map），再服务层 `validateAll`（业务规则，400 TEST_CASE_400_RULE）。
- 唯一性约束：`caseCode` + `version` 联合唯一；已软删除的用例编码仍占用唯一键，无法复用。
- `scenarioType` 为空时服务端落库为 `AUTO`（`TestCaseScenario`（domain 常量类） 语义，domain 模型 `effectiveOrDefault`）。
- 创建成功后同步写入判定规则（judge_rule 表，`combineMode` 取自用例级字段）。

##### 错误响应

| HTTP | code | 触发条件 | msg |
|:----:|:----:|----------|-----|
| 400 | COMMON_400_VALIDATION | 请求体不满足 `@Valid` 约束（data 为字段错误 Map）；请求体非 JSON 或字段类型错误；`id` 非正整数 | `"Validation failed"` |
| 404 | TEST_CASE_NOT_FOUND | 目标用例不存在或已软删除（先执行 get(id)） | `"Test case not found"` |
| 400 | TEST_CASE_400_RULE | 服务层规则校验失败（同接口 2，data=null） | `"Invalid test case rule"` |
| 409 | COMMON_409_CONFLICT | 请求体 `caseCode`+`version` 被**其它**用例（id 不同）占用 | `"Resource conflict"` |

---

#### 业务规则

- 更新为全量覆盖：先 `UPDATE test_case` 主记录，再 `DELETE` 原 rules 后整体重插 judge_rule 行（非增量合并）。
- 唯一性冲突检查排除自身（`filter(found -> !found.id().equals(id))`），自身编码不变不报 409。
- `createdAt` 从原记录继承，不随更新改变。

### 5 删除测试用例（软删除）

| **接口说明** | 软删除测试用例（deleted_at 置当前时间），保留历史引用（任务快照/评测结果不受影响） |
| **认证方式** | 无需认证 |
| **权限要求** | 无 |
| **标签** | test-cases |

#### 请求

**请求头**: [公开]

**路径参数表**：

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|:---:|------|------|

#### 响应

##### 成功响应 — HTTP 200

响应体：`ApiResponse<TestCaseDeletionResult>`

- 外层包装：[ApiResponse](../entities/ApiResponse.md)（code=`"200"`，message=`"success"`）
- data：[TestCaseDeletionResult](../entities/TestCaseDeletionResult.md)（testCaseId + action=`"SOFT_DELETED"`）

```json
{
  "code": "200",
  "message": "success",
  "data": {
    "testCaseId": 1,
    "action": "SOFT_DELETED"
  },
  "traceId": "test-case-001"
}
```

##### 错误响应

| HTTP | code | 触发条件 | msg |
|:----:|:----:|----------|-----|
| 400 | COMMON_400_VALIDATION | `id` 非正整数 | `"Validation failed"` |
| 404 | TEST_CASE_NOT_FOUND | 用例不存在（`selectByIdForUpdate` 查不到主记录；已软删除的用例重复删除不报错，仍返回 200） | `"Test case not found"` |
| 500 | COMMON_500_INTERNAL | 未预期异常 | `"Internal server error"` |

---

#### 业务规则

- 软删除语义：`deleted_at = COALESCE(deleted_at, CURRENT_TIMESTAMP(3))`，物理行保留；唯一键（caseCode+version）仍占用，无法重建同编码用例。
- 幂等性：已软删除的用例再次 DELETE 返回 200 且 `action` 仍为 `"SOFT_DELETED"`（主记录仍在，SELECT FOR UPDATE 可命中）。
- 该接口不返回 601 警告类结果，删除不受引用限制（历史引用天然保留）。

```json
      "expectedTool": null,
      "expectedToolParameters": null,
      "factReferences": null,
      "weight": 0.2,
      "passScore": 80,
      "scenarioType": "AUTO",
      "version": "1.0.0",
      "enabled": true,
      "createdAt": "2026-08-19T10:00:00+08:00",
      "updatedAt": "2026-08-19T10:00:00+08:00",
      "rules": []
    }
  ],
  "traceId": "test-case-001"
}
```

##### 错误响应

任一校验错误（含行级错误）时返回 **HTTP 400**，响应体为 `ApiResponse<List<ImportError>>`：

- 外层：[ApiResponse](../entities/ApiResponse.md)（code=`COMMON_400_VALIDATION`，message=`"Validation failed"`）
- data：行级错误数组，元素为 [ImportError](../entities/ImportError.md)（rowIndex/field/errorCode/message）；错误按 rowIndex → field → errorCode → message 升序排列，同一 (rowIndex, field) 去重

```json
{
  "code": "COMMON_400_VALIDATION",
  "message": "Validation failed",
  "data": [
    {
      "rowIndex": 1,
      "field": "weight",
      "errorCode": "COMMON_400_VALIDATION",
      "message": "weight must be greater than 0"
    },
    {
      "rowIndex": 2,
      "field": "caseCode",
      "errorCode": "COMMON_409_CONFLICT",
      "message": "caseCode and version already exist"
    }
  ],
  "traceId": "test-case-001"
}
```

| HTTP | code（外层） | data 内 errorCode | 触发条件 | msg（data 内 message） |
|:----:|:----:|:----:|----------|-----|
| 400 | COMMON_400_VALIDATION | COMMON_400_VALIDATION | 请求体为 null 或非数组 | `"Import request array is required"`（rowIndex=0, field="request"） |
| 400 | COMMON_400_VALIDATION | COMMON_400_VALIDATION | 数组元素为 null | `"Import row is required"`（field="request"） |
| 400 | COMMON_400_VALIDATION | COMMON_400_VALIDATION | 行元素不满足 `@Valid` 约束（caseCode/caseName/version 为空、weight/passScore 越界、rules 为空等） | Bean Validation 消息（如 `"must not be blank"`） |
| 400 | COMMON_400_VALIDATION | TEST_CASE_400_RULE | 服务层规则校验失败（indicatorId 不存在或非启用 CORE 指标、SINGLE_TURN 缺 question、MULTI_TURN 轮次不足、规则配置非法等） | `"Indicator does not exist"`、`"MULTI_TURN requires at least two turns"` 等 |
| 400 | COMMON_400_VALIDATION | COMMON_409_CONFLICT | 批内出现重复 caseCode+version | `"Duplicate caseCode and version in import batch"` |
| 400 | COMMON_400_VALIDATION | COMMON_409_CONFLICT | caseCode+version 已存在于库中（含软删除记录） | `"caseCode and version already exist"` |
| 400 | COMMON_400_VALIDATION | COMMON_409_CONFLICT | 数据库唯一键兜底冲突（saveAll 时 DuplicateKeyException） | `"Database rejected duplicate caseCode and version"`（field="caseCode/version"） |
| 400 | COMMON_400_VALIDATION | COMMON_400_VALIDATION | JSON 语法错误/字段类型无法反序列化（HttpMessageNotReadableException 按路径定位行号） | `"Invalid JSON value for {field}"`（rowIndex=出错元素下标） |
| 500 | COMMON_500_INTERNAL | — | 未预期异常 | `"Internal server error"` |

---

#### 业务规则

- **整体成败**：只要存在任一错误（含行级），`imported` 返回空列表，**没有任何行落库**（先全量校验，错误非空即短路返回）。
- `rowIndex` 为数组下标（从 0 开始）；JSON 解析错误的行号取自 Jackson JsonMappingException 的 path 下标。
- 行级校验顺序：@Valid（Controller 预校验，errorCode=COMMON_400_VALIDATION）→ 服务层规则校验（TEST_CASE_400_RULE）→ 批内/库内唯一性检查（COMMON_409_CONFLICT）。
- 错误列表去重键为 (rowIndex, field)，排序后返回；外层 HTTP/code/message 恒定 400 + COMMON_400_VALIDATION，行级 errorCode 字段承载具体错误码。

### 7 Excel 导入测试用例

| 属性 | 值 |
|------|-----|
| **请求方式** | `POST` |
| **接口路径** | `/api/test-cases/import/excel` |
| **接口说明** | 从 .xlsx 工作簿导入测试用例（Content-Type: multipart/form-data）；文件缺失/为空或解析失败返回 400 + ImportError 列表 |
| **认证方式** | 无需认证 |
| **权限要求** | 无 |
| **标签** | test-cases, import, excel |
| **Content-Type** | `multipart/form-data`（Controller `consumes = MediaType.MULTIPART_FORM_DATA_VALUE`，其它类型直接 415） |

---

#### 请求

**请求头**: [公开]（Content-Type 必须为 `multipart/form-data`）

**请求参数**（form-data 表单字段）：

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|:---:|------|------|
| `file` | MultipartFile | 是 | Excel 工作簿（.xlsx），要求第一行为表头 | `test-cases.xlsx` |
| `indicatorId` | Long | 否 | 默认指标 ID：应用到所有未填 indicatorId 列的行；缺省为 0（各行必须自带 indicatorId） | `1001` |

无 JSON 请求体。

---

#### 响应

##### 成功响应 — HTTP 200

响应体：`ApiResponse<List<TestCaseResponse>>`（结构与接口 6 成功响应相同）

- 外层包装：[ApiResponse](../entities/ApiResponse.md)（code=`"200"`，message=`"success"`）
- data：已导入用例数组，元素为 [TestCaseResponse](../entities/TestCaseResponse.md)

##### 错误响应

任一错误（含行级）时返回 **HTTP 400**，响应体为 `ApiResponse<List<ImportError>>`（外层 code=`COMMON_400_VALIDATION`，message=`"Validation failed"`；data 元素为 [ImportError](../entities/ImportError.md)）：

| HTTP | code（外层） | data 内 errorCode | 触发条件 | msg（data 内 message） |
|:----:|:----:|:----:|----------|-----|
| 400 | COMMON_400_VALIDATION | COMMON_400_VALIDATION | `file` 缺失或为空文件 | `"Excel file is required"`（rowIndex=0, field="file"） |
| 400 | COMMON_400_VALIDATION | COMMON_400_VALIDATION | 首行无表头 / 工作簿为空 / 无数据行 | `"Excel file must contain a header row"`、`"Excel file contains no test case rows"` 等（rowIndex=0, field="file"） |
| 400 | COMMON_400_VALIDATION | COMMON_400_VALIDATION | 复杂列（conversationTurns/factReferences/rules/expectedToolParameters）单元格 JSON 非法 / 非法枚举值 | `"{column} column is not a valid JSON array"`、`"rules column is not a valid JSON array"` 等（rowIndex=0, field="file"） |
| 400 | COMMON_400_VALIDATION | COMMON_400_VALIDATION | 文件流读取失败 | `"Unable to read the Excel file"`（rowIndex=0, field="file"） |
| 400 | COMMON_400_VALIDATION | TEST_CASE_400_RULE | 行级服务层规则校验失败（同接口 6，field 为具体字段） | `"Indicator does not exist"` 等（rowIndex=物理行号） |
| 400 | COMMON_400_VALIDATION | COMMON_409_CONFLICT | 批内重复 / 库中已存在 caseCode+version（同接口 6） | `"Duplicate caseCode and version in import batch"`、`"caseCode and version already exist"` |
| 500 | COMMON_500_INTERNAL | — | 未预期异常（模板生成等） | `"Internal server error"` |

---

#### 业务规则

- 解析规则：取第一个 Sheet，第一行为表头（表头名大小写不敏感），自第二行起逐行读取；空白行跳过；解析出的行数为 0 报 400。
- **缺列/空值回退默认值**（优先级：请求参数 indicatorId > 配置 `evaluation.test-case-import.*` > 代码默认）：
  - `caseCode` 为空 → 自动生成 `XC-` + 12 位大写十六进制随机串；
  - `indicatorId` 为空 → 请求参数 `indicatorId`（未传则为 0，行级校验必然报 "indicatorId must be positive"）；
  - `caseType` 默认 `SINGLE_TURN`、`version` 默认 `1.0.0`、`weight` 默认 `1`、`passScore` 默认 `60`、`combineMode` 默认 `ALL`、`enabled` 默认 `true`；
  - `rules` 为空 → 单条默认规则（judgeType 默认 `AI_SEMANTIC_SCORE`，ruleOrder=1，weight=1，required/enabled=true，ruleConfig 取配置默认）。
- 复杂字段以 **JSON 字符串** 填充单元格：`conversationTurns`/`factReferences` 为 JSON 数组，`expectedToolParameters`/`rules` 为 JSON 对象/数组。
- 行级错误 `rowIndex` 为 Excel **物理行号**（表头行为第 1 行，数据行从 2 开始，rowIndex=0 特指文件级错误）。
- 与 JSON 导入一致：整体成败，任一错误则所有行不落库。
