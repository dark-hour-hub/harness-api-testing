# 智能体模块 API 文档

> Controller: `com.czbank.aicgs.evaluation.agent.adapter.in.web.AgentController` | Base URL: `http://localhost:8080` | Auth: 无（auth_type: none，所有接口公开访问）

## 请求头

| 头名称 | 值 | 说明 |
|--------|-----|------|
| Content-Type | `application/json` | 请求体格式（本模块无文件上传） |
| X-Trace-Id | `{自定义字符串}` | 可选，链路追踪 ID（TraceIdFilter 透传并回写响应头）；缺失时服务端生成 32 位十六进制 UUID，永不因缺失报错 |

> 认证说明：全项目无任何认证机制，无 `Authorization`/`clientid` 等鉴权头，无权限模型。
>
> 响应包装：所有接口响应体均为 [ApiResponse](../entities/ApiResponse.md)（code="200"/message="success" 表示成功）；分页数据为 [PageResult](../entities/PageResult.md)（items/page/pageSize/total，pageSize 上限 100）。
>
> 错误响应统一由 `GlobalExceptionHandler` 处理：HTTP 状态码 = ErrorCode.httpStatus()，响应体 code = ErrorCode.name()，message = ErrorCode.defaultMessage()（硬编码，无 i18n）。本模块涉及的错误码：
>
> | code | HTTP | message |
> |------|:----:|---------|
> | COMMON_400_VALIDATION | 400 | `"Validation failed"` |
> | COMMON_404_RESOURCE | 404 | `"Resource not found"` |
> | COMMON_409_CONFLICT | 409 | `"Resource conflict"` |
> | AGENT_400_CONFIG | 400 | `"Invalid agent configuration"` |
> | COMMON_500_INTERNAL | 500 | `"Internal server error"` |

#### 请求

**请求头**: [公开]

**查询参数表**（全部由 Controller 手工解析，类型声明为 String 但按下列规则转换）：

| 参数名 | 类型 | 必填 | 匹配方式 | 说明 | 示例 |
|--------|------|:---:|:---:|------|------|
| `agentCode` | String | 否 | like | Agent 编码模糊过滤（LIKE `%value%`） | `"AGENT"` |
| `agentName` | String | 否 | like | Agent 名称模糊过滤（LIKE `%value%`） | `"客服"` |
| `riskTier` | String | 否 | eq | 风险等级精确过滤，合法值 `A`/`B`/`C`/`D`；非法值报 400 | `"B"` |
| `adapterType` | String | 否 | eq | 适配器类型精确过滤，合法值 `MINI_ZHEXIAOZHI`/`GENERIC_HTTP_JSON`；非法值报 400 | `"GENERIC_HTTP_JSON"` |
| `enabled` | String | 否 | eq | 启用状态精确过滤，合法值 `true`/`false`（大小写不敏感）；非法值报 400 | `"true"` |
| `page` | String | 否 | — | 页码，从 1 开始，默认 `1`；小于 1 或非数字报 400 | `1` |
| `pageSize` | String | 否 | — | 每页条数，默认 `20`，范围 1~100；越界或非数字报 400 | `20` |

> 匹配方式映射：`eq`=精确匹配，`like`=模糊匹配（LIKE CONCAT('%', #{value}, '%')）。
>
> 排序固定：`ORDER BY updated_at DESC, id DESC`，无排序参数。
>
> 空值/空白字符串的筛选参数按未传处理（SQL 层 `<if>` 判空跳过）。

无请求体。

#### 业务规则

| 规则 | 说明 |
|------|------|
| 必填字段 | agentCode、agentName、category、riskTier、version、agentType、adapterType、endpoint、method、timeoutMs 均必填，缺失报 `AGENT_400_CONFIG` |
| agentCode 格式 | 须匹配正则 `[A-Z0-9_]{2,64}`（大写字母/数字/下划线，2~64 位），且全局唯一（与已有记录冲突报 409） |
| endpoint 校验 | 必须是合法 URI 且 scheme 为 http/https、host 非空 |
| timeoutMs 范围 | 100 ≤ timeoutMs ≤ 120000 |
| headerSecretRef | 可选；须匹配 `env:{NAME}` / `secret:{label}` / `app-{alphanumeric}` 引用格式；禁止包含 authorization/bearer/basic；`secret:` 标签禁止为 password/token/accesstoken/apikey |
| requestTemplate | 若提供必须是合法 JSON（Jackson 解析） |
| JSON 路径字段 | messageField/sessionField/answerField/successField/errorField/latencyField/tokenField/toolTraceField 若非空须可被 JsonPath 编译 |
| 适配器约束 | `adapterType=GENERIC_HTTP_JSON` 时 `answerField` 必填 |
| enabled 缺省 | 缺省视为 `true` |
| 幂等性 | 不幂等，重复提交同 agentCode 返回 409 |

#### 业务规则

| 规则 | 说明 |
|------|------|
| 引用判断 | 查询 `evaluation_task.agent_id` 是否存在指向该 Agent 的记录（countTaskReferences） |
| 有引用 → 软禁用 | 执行 `UPDATE agent_config SET enabled=false, updated_at=CURRENT_TIMESTAMP(3)`，保留记录供历史任务追溯 |
| 无引用 → 物理删除 | 执行 `DELETE FROM agent_config WHERE id={id}` |
| 不存在处理 | 先查后删，ID 不存在报 404 COMMON_404_RESOURCE |
| 响应载荷 | 成功时 data 恒为 null，调用方以 code="200" 判断结果 |
