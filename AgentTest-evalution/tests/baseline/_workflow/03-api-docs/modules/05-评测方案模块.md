# 评测方案模块 API 文档

> Controller: `com.czbank.aicgs.evaluation.scheme.adapter.in.web.EvaluationSchemeController` | Base URL: `http://localhost:8080` | Auth: 无（auth_type: none，所有接口公开访问）

## 请求头

| 头名称 | 值 | 说明 |
|--------|-----|------|
| Content-Type | `application/json` | 请求体格式（本模块无文件上传） |
| X-Trace-Id | `{自定义字符串}` | 可选，链路追踪 ID（TraceIdFilter 透传并回写响应头）；缺失时服务端生成 32 位十六进制 UUID，永不因缺失报错 |

> 认证说明：全项目无任何认证机制，无 `Authorization`/`clientid` 等鉴权头，无权限模型。
>
> 响应包装：所有接口响应体均为 [ApiResponse](../entities/ApiResponse.md)（code=`"200"`/message=`"success"` 表示成功）；分页数据为 [PageResult](../entities/PageResult.md)（items/page/pageSize/total，pageSize 上限 100）。
>
> 错误响应统一由 `GlobalExceptionHandler` 处理：HTTP 状态码 = ErrorCode.httpStatus()，响应体 code = ErrorCode.name()，message = ErrorCode.defaultMessage()（硬编码，无 i18n）。本模块涉及的错误码：
>
> | code | HTTP | message |
> |------|:----:|---------|
> | COMMON_400_VALIDATION | 400 | `"Validation failed"` |
> | SCHEME_400_INVALID | 400 | `"Invalid evaluation scheme"` |
> | SCHEME_NOT_FOUND | 404 | `"Evaluation scheme not found"` |
> | COMMON_409_CONFLICT | 409 | `"Resource conflict"` |
> | SCHEME_409_STATUS | 409 | `"Evaluation scheme status conflict"` |
> | SCHEME_ALREADY_ARCHIVED | 409 | `"Evaluation scheme is already archived"` |
> | DRAFT_SCHEME_REFERENCED | 409 | `"Draft evaluation scheme is referenced"` |
> | SCHEME_DELETE_CONFLICT | 409 | `"Evaluation scheme deletion conflict"` |
> | COMMON_500_INTERNAL | 500 | `"Internal server error"` |
>
> 方案生命周期状态机（`SchemeStatus`）：`DRAFT` → `PUBLISHED` → `ARCHIVED`。仅 `DRAFT` 可更新/发布/校验；仅 `PUBLISHED`/`ARCHIVED` 可克隆；`ARCHIVED` 不可删除。

#### 请求

**请求头**: [公开]

**查询参数表**（全部由 Controller 手工解析，类型声明为 String 但按下列规则转换）：

| 参数名 | 类型 | 必填 | 匹配方式 | 说明 | 示例 |
|--------|------|:---:|:---:|------|------|
| `schemeCode` | String | 否 | like | 方案编码模糊过滤（LIKE `%value%`） | `"SCHEME"` |
| `schemeName` | String | 否 | like | 方案名称模糊过滤（LIKE `%value%`） | `"年度"` |
| `status` | String | 否 | eq | 方案状态，合法值 `DRAFT`/`PUBLISHED`/`ARCHIVED`；非法值报 400 | `"PUBLISHED"` |
| `evaluationMode` | String | 否 | eq | 评测模式，合法值 `COMPREHENSIVE`/`SPECIAL`；非法值报 400 | `"COMPREHENSIVE"` |
| `evaluationType` | String | 否 | eq | 评测类型（已弃用），合法值 `ENTRY`/`REGRESSION`/`RUNNING`/`SECURITY_SPECIAL`；非法值报 400 | `"ENTRY"` |
| `riskTier` | String | 否 | eq | 风险等级，合法值 `A`/`B`/`C`/`D`；非法值报 400 | `"B"` |
| `page` | String | 否 | — | 页码，从 1 开始，默认 `1`；小于 1 或非数字报 400 | `1` |
| `pageSize` | String | 否 | — | 每页条数，默认 `20`，范围 1~100；越界或非数字报 400 | `20` |

> 匹配方式映射：`eq`=精确匹配，`like`=模糊匹配（LIKE CONCAT('%', #{value}, '%')）。
>
> 空值/空白字符串的筛选参数按未传处理（SQL 层 `<if>` 判空跳过）。

无请求体。

| 默认权重 | `dimensionWeights` 未传 → 按 `riskTier` + 目录版本应用 `SchemeDefaultWeightPolicy` |
| 布尔默认值 | `safetyVetoEnabled`/`stopOnSafetyFailure` 为 null 时按 `true` 处理 |

#### 响应

##### 成功响应 — HTTP 200

响应体：`ApiResponse<SchemeDeletionResult>`

- 外层包装：[ApiResponse](../entities/ApiResponse.md)
- data：[SchemeDeletionResult](../entities/SchemeDeletionResult.md)（action 取值 `PHYSICALLY_DELETED`/`ARCHIVED`；`newStatus` 物理删除时为 null，归档时为 `ARCHIVED`）

物理删除示例：

```json
{
  "code": "200",
  "message": "success",
  "data": {
    "id": 1,
    "originalStatus": "DRAFT",
    "action": "PHYSICALLY_DELETED",
    "taskReferenceCount": 0,
    "reportReferenceCount": 0,
    "newStatus": null
  },
  "traceId": "test-case-001"
}
```

归档示例（已发布且被引用）：

```json
{
  "code": "200",
  "message": "success",
  "data": {
    "id": 1,
    "originalStatus": "PUBLISHED",
    "action": "ARCHIVED",
    "taskReferenceCount": 3,
    "reportReferenceCount": 1,
    "newStatus": "ARCHIVED"
  },
  "traceId": "test-case-001"
}
```

##### 错误响应

| HTTP | code | 触发条件 | msg |
|:----:|:----:|----------|-----|
| 400 | COMMON_400_VALIDATION | `id` 非数字或 <1 | `"Validation failed"` |
| 404 | SCHEME_NOT_FOUND | 方案不存在 | `"Evaluation scheme not found"` |
| 409 | SCHEME_ALREADY_ARCHIVED | 方案已归档 | `"Evaluation scheme is already archived"` |
| 409 | DRAFT_SCHEME_REFERENCED | 草稿方案被任务/报告引用 | `"Draft evaluation scheme is referenced"` |
| 409 | SCHEME_DELETE_CONFLICT | 物理删除时记录并发变更（删除行数 ≠1） | `"Evaluation scheme deletion conflict"` |
| 500 | COMMON_500_INTERNAL | 未预期异常 | `"Internal server error"` |

---

#### 业务规则

| 规则 | 说明 |
|------|------|
| 决策逻辑 | DRAFT 且被引用 → 409 拒绝；PUBLISHED 且被引用 → 归档；其余 → 物理删除（级联删除子选择） |
| 事务性 | 删除在 `REPEATABLE_READ` 事务内执行，先查引用后决策 |
| 幂等性 | 已归档方案再次删除 → 409 |
